# ضماني — نموذج أولي معزول لمحرك التراخيص

**للتجارب فقط؛ غير متصل بتطبيق ضماني ولا يصلح للإنتاج أو تحصيل أموال العملاء.**

ينفذ هذا النموذج: اعتماد الدفع يدويًا، إنشاء رمز تفعيل عشوائي، ربط جهاز واحد، التحقق كل 30 يومًا بشهادة Ed25519، نقل الربط، إيقاف الترخيص، وسجل عمليات داخل الذاكرة.

التجربة: `node --test licensing-prototype/engine.test.mjs` باستخدام Node.js 22 أو أحدث.

القيود الأمنية المتعمدة: لا توجد واجهة شبكة أو لوحة إدارة أو قاعدة بيانات دائمة أو مصادقة مالك أو إثبات حيازة المفتاح الخاص للجهاز. يعتمد النموذج على سلسلة المفتاح العام كما هي، ولا يمنع نسخها؛ لا تستخدمه كنظام تفعيل فعلي. كما أن إبطال شهادة صادرة يحتاج اتصالًا جديدًا، فلا يمكن منع الجهاز القديم من استخدامها خلال مهلة عدم الاتصال. يجب تنفيذ خادم خاص، قاعدة بيانات معاملات، مصادقة قوية، وتخزين مفاتيح الجهاز في Keychain/Keystore قبل البيع.

## إثبات حيازة مفتاح الجهاز (نموذج تجريبي)

أضيفت دالتا `issueChallenge` و`completeChallenge`: يصدر المحرك تحديًا عشوائيًا قصير العمر (120 ثانية) لغرض التفعيل أو التحقق، ويوقّع العميل النص `dhamani-device-proof-v1:<purpose>:<challengeId>:<nonce>` بمفتاح Ed25519 الخاص. يتحقق الخادم من التوقيع بالمفتاح العام المسجل، ويستهلك التحدي مرة واحدة حتى لو فشل التوقيع. هذه الآلية تمنع الاكتفاء بنسخ المفتاح العام، لكنها لا تضمن ربطه بجهاز مادي دون تخزين مفتاح خاص غير قابل للتصدير. **واجهتا `activate` و`verify` القديمتان باقيتان لأغراض الاختبار فقط، وتتجاوزان التحدي؛ يجب إزالتهما من الواجهة العامة قبل الإنتاج.**
